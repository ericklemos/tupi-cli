# Tupi CLI v1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar o chat de terminal do Tupi: TUI ratatui com streaming DeepSeek, sobre workspace microkernel + CQRS.

**Architecture:** Workspace de seis crates com regra de dependência unidirecional (`domain` ← `kernel` ← `providers`/`app`/`tui` ← bin). O kernel define `Provider`, `CommandBus`, `QueryBus` e `EventBus`; o app implementa os handlers; a TUI só despacha comandos e reage a eventos.

**Tech Stack:** Rust 1.99 (edition 2021), tokio, ratatui, crossterm, reqwest (rustls), serde/serde_json, async-trait, futures-util, thiserror/anyhow, tracing.

**Spec:** `docs/superpowers/specs/2026-11-10-tupi-cli-design.md`

## Global Constraints

- Edition 2021, resolver 2, versão 0.1.0 em todos os crates; dependências em `[workspace.dependencies]`.
- `tupi-tui` não depende de `tupi-providers` nem de `tupi-app`; `tupi-providers` não depende de `tupi-app`. Só o crate `tupi` conhece todos.
- Chave: `TUPI_CLI_DEEPSEEK_PLATAFORM_APIKEY` (grafia exata). Modelo: `TUPI_MODEL`, padrão `deepseek-flash`. Log: `TUPI_LOG`, padrão `warn`.
- Endpoint: `https://api.deepseek.com/chat/completions`, `stream: true`, campo `thinking` omitido.
- Streaming: token a token; timeout de conexão 10 s; watchdog de 120 s sem bytes.
- Um stream por vez; segundo `SendMessage` durante streaming → `CommandError::Busy`.
- Texto puro na UI, sem markdown. Chave e corpos de mensagem nunca são logados.
- O repo pode não estar sob git: se `git` não estiver disponível, os passos de commit são registro e a verificação é `cargo test`.

## Review Focus

- **Chunk SSE partido no meio de um caractere UTF-8 ou de uma linha** → nenhum caractere perdido nem JSON truncado (teste na Task 3).
- **Chave ausente no ambiente** → erro antes de abrir a TUI, citando o nome exato da variável (teste na Task 8).
- **Envio durante streaming** → `Busy`, texto preservado no input, sem duas respostas concorrentes (teste na Task 5).
- **Cancelamento no meio do stream** → texto parcial preservado no histórico e estado volta a idle (teste na Task 5).
- **Assinante do EventBus atrasado** → `Lagged` não derruba o loop da TUI (teste na Task 2; tratamento na Task 7).

fn handles_line_and_utf8_split_across_chunks() {
    let mut p = SseParser::new();
    let text = "data: {\"choices\":[{\"delta\":{\"content\":\"olá\"}}]}\n\n";
    let bytes = text.as_bytes();
    let cut = text.find("á").unwrap() + 1; // corta dentro do 'á'
    assert!(p.push(&bytes[..cut]).is_empty());
    let out = p.push(&bytes[cut..]);
    assert_eq!(out, vec![text[6..text.len() - 2].to_string()]);
    assert_eq!(extract_delta(&out[0]).unwrap(), Some("olá".into()));
}

async fn send_message_publishes_tokens_and_appends_history() {
    let bus = EventBus::new(16);
    let mut rx = bus.subscribe();
    let app = App::new(fake_registry(vec!["a", "b"]), "fake", "m".into(), bus);
    let outcome = app.handle(Command::SendMessage { text: "oi".into() }).await.unwrap();
    let CommandOutcome::Started { request_id } = outcome else { panic!() };
    assert_eq!(rx.recv().await.unwrap(), Event::Token { request_id, text: "a".into() });
    assert_eq!(rx.recv().await.unwrap(), Event::Token { request_id, text: "b".into() });
    assert_eq!(rx.recv().await.unwrap(), Event::StreamFinished { request_id });
    let QueryResult::History(h) = app.query(Query::History).await.unwrap();
    assert_eq!(h.len(), 2);
    assert_eq!(h[1].content, "ab");
}
